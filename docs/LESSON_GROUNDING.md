# Lesson grounding after the before/after evaluation

Implemented September 15, 2026. Previous version: `ff1ab85` on `origin/main`.

## Changes

The normal and detailed report generation and engine analysis pipeline are unchanged. The
existing main Markdown remains sufficient; no additional application JSON upload or new game
analysis is needed to try this skill. All extra reading/verification files are generated by the
skill from that report or from independently researched puzzle positions.

- `teaching_facts.py` supplies actual moves, explicitly alternating sequence players, coordinate
  orientation, local defender identity, policy attribution and signed sampled comparisons.
  It checks relevant groups' liberties before and after the played/preferred move. Source hints,
  full variations, commentary and all existing report data remain available.
- Current statistics come from current accuracy and phase records. Suspected earlier analyses
  of the same game are separated using matching metadata, and excluded from comparison rows.
  The original history is preserved. This is conservative metadata matching, not a proof of game
  identity and not new cross-game pattern mining.
- New authored lessons use `grounding_version: 1`. Fact tokens expand directly from derived data;
  `fact_checks` validate referenced values and quotations in the actual draft. The skill requires
  a sentence-by-sentence audit of fragile factual claims. These checks cannot certify the meaning
  of unrestricted prose: an agent can still write an unsupported causal interpretation.
- New quizzes identify a specific external example, record its original board and meaningful
  transformation, and give an explicit objective. Board assertions are replayed. Bounded capture
  goals are checked against all legal replies for each offered choice; insufficient search work
  yields inconclusive, never an invented proof. Capturing within a horizon and surviving for a
  horizon are distinct from whole-board optimality and unconditional life.
- An optional local KataGo helper searches an exact newly composed puzzle and offered choices.
  Its evidence includes position/rules/komi fingerprint, Black-view scores and engine paths. The
  validator rejects mismatched artifacts and choices insufficiently distinguished by search.
  If the external agent has no KataGo, it can use bounded capture checks or sufficiently verified
  reading/external solutions. Research remains uncapped. Actual-game puzzle reuse is prohibited.
- Praise no longer needs an invented rank. Human sequences can have their own explanations;
  otherwise the UI labels engine/general commentary. Sample-result descriptions explicitly name
  the favoured start and local predictions name the defender. Overview, development and progress
  remain accessible in an expandable section above the boards. Unlisted puzzle clicks are
  unverified, not automatically wrong.

## Analysis config clarification

An empty saved override previously displayed “automatic (built-in config)” even when KaTrain's
external config was selected. The app now shows the selected path beside the override field.
Resolution order is flag/environment → saved Go Teacher setting → external KaTrain config →
`~/.katago/default_analysis.cfg` → embedded default. The standard ~/.katago fallback is new.
Invalid explicitly chosen paths still fail visibly rather than silently using a different config.
No user settings or KaTrain configuration files were edited.
